# ADR-010 — スコープの境界：Option は分離、最終決定は人、手書き記号と品質に AI / OCR は使わない

| 状態 | 日付 | 決定者 | 置換 |
|---|---|---|---|
| **Accepted**（§6 の顧客待ちの点を除く） | 2026-11-26 | 受講者（L4-D09）、PL が提案 | — |

## 1. 背景

- ルール3 / CAP-HUMAN-01：最終決定は人が行う — 目利き（品質 / 鮮度の評価）、せりの結果の確定、機微な修正の決裁、配送紛争の確認。SCOPE-OUT-01/02：品質 / 魚種の自動判定はしない；手書きの記号（手やり）や符丁（市場独自の価格コード）を OCR / AI でデータに変換しない。SCOPE-OUT-06：AI を置く場合も提案のみ。
- ルール6：Option（遠隔取引、買受人ポータル、分析 / 予測、AI の提案のみ）は常に、範囲・前提・費用・リスクを分けて扱う（PRM-024, DEC-008）。第2期の17項目は第1期の範囲外。
- PREMISE §1.2：アーキテクチャは**名前付きの拡張ポイント**のみ残す；Option の詳細設計はしない。
- 実際のリスク（構築時）：「ついでに」せりの伝票への OCR や、主画面への価格の提案を入れてしまい、ルール3 / 6 に違反しても誰も決めていない状態。

## 2. 決定

1. **第1期には AI / OCR / 認識の機能を一切含めない。** 目利き、せり、配送確認の結果は人が入力したデータで、各レコードに人と時刻を持つ（ARCHITECTURE §6）。
2. 人が決める点は **UI だけでなく DB で強制**：せりの確認は入力者とは別の人が行う（同一人物なら理由 + 要確認フラグ）；修正申請と配送紛争の確認は自己決裁を禁止；日次締め / 期ロックは自動実行のジョブを持たない（ADR-003, ADR-005）。
3. **名前付きの拡張ポイント**（詳細は ARCHITECTURE §10）— 境界のみで、第1期にはコードはない：
   - *外部向けポータル*（SCOPE-OUT-03/04、第2期の SEC-IAM-02）：専用のルートグループと認証レルム、モジュールの公開サービスのみ呼び出す。
   - *分析 / 予測*（08-06）：S3 にある構造化された出力データ（FR-RPT-03）から読む。業務 DB を直接照会しない。
   - *AI（提案のみ）*（SCOPE-OUT-06）：提案は**専用のテーブル**に書く；AI のコンポーネントは業務の書き込み関数への **EXECUTE 権限を持たない**；利用者が提案を受け入れる = その人が自分で入力 / 確認し、名前を記録する。
   - *ラベル / ロットコードのスキャン*（改善 04-07）：ロットコードは一意で、バーコードとして印刷可能。
4. 3 のいずれかを追加する場合 = **CR / 個別の単価**。範囲・前提・費用・リスクを明記した新しい ADR が必要。

## 3. 検討した選択肢

| 案 | 長所 | 短所 | 結論 |
|---|---|---|---|
| **A. 第1期は AI / OCR なし；名前付きの拡張ポイント；人の決定は DB で強制（採用）** | ルール3、6 に一致；誰も払わないものは設計しない；Option を後で入れてもコアを変えなくて済む | 「賢い機能」をデモできない | **採用** |
| B. せりの伝票 / 手やりを OCR して入力の手間を減らす | 入力が減る | SCOPE-OUT-02 に反する；誤認識がそのまま金額に入る | 却下 |
| C. 主画面に AI の価格 / 品質の提案を置き、人が承諾する | 役に立つ | SCOPE-OUT-06 の Option で別に価格がかかる；ルール6 に反して基本スコープに入れる | 第1期からは除外（Option） |
| D. ポータル / 遠隔取引の詳細設計を「念のため」用意 | 第2期の作業が減る | 誰も払わない設計になり、顧客の決定が変わるとずれる | 却下（YAGNI） |
| E. 境界を何も残さない | 最も単純 | 第2期でコア（認証、関数の呼び出し権限）を変更する必要がある | 却下 |

## 4. 結果

**良い点**
- 提案書 / コンプライアンスとアーキテクチャが同じことを言う：システムは人の決定を記録するのであり、人に代わって決めない。
- 権限の境界（AI は書き込み関数に EXECUTE なし）により、Option を追加してもルール3 が成り立つ。

**悪い点 / リスク**
- 02-05、BR-NOTIFY-01（外部の人の部分）、SEC-IAM-02 は第1期では「一部対応」のみ（L4-A08）— LAB-1 のコンプライアンスに記載済み（DEC-023）。

**派生する作業**
- LAB-5 のコードレビュー：「OCR / AI のライブラリがない、AI の API を呼ばない」のチェックリスト。
- Option を購入する場合 → 該当部分を置き換える新しい ADR を作る（§3 の項目）。

## 5. トレーサビリティ

ルール3, ルール6；CAP-HUMAN-01；SCOPE-OUT-01..04, SCOPE-OUT-06；04-07, 08-06, 02-05, BR-NOTIFY-01, SEC-IAM-02, FR-RPT-03, FR-SERI-01；PRM-024, PRM-115；DEC-008, DEC-023；L4-A08；PREMISE §1.2。

## 6. 顧客待ちの点

§2 の決定は **Accepted**（L4-D09）。この境界を変える顧客待ちの点はない：ルール3（最終決定は人、AI / OCR なし）は RFP の条件である。顧客が Option を購入するかどうか（遠隔取引、買受人ポータル、分析 / 予測、AI の提案のみ）は価格の範囲を決めるだけで、分離すること自体は変わらない。
