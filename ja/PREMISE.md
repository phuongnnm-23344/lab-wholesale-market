# LAB-4 設計の前提条件（PREMISE）

本文書は、LAB-4設計一式の土台とするために、LAB-1（見積・提案）とLAB-2（実際に動くプロトタイプ）の後に追加した決定を記録するものです。`architecture/`、`wireframes/`、`specs/` の文書はすべてここの前提条件と一致していなければなりません。ずれがあれば該当文書を修正するか、本ファイルのバージョンを上げてください。二か所で異なる内容を書かないようにします。

## 0. 読み方

| 記号 | 意味 |
|---|---|
| `FR-` `NFR-` `BR-` `SCOPE-` `ACC-` `GOV-` `CAP-` `TBL-` … | 顧客RFP（`v1.0-rc7` 版）のID。本文書ではIDを示し、意図を言い換えるのみで、RFPの原文は転記しない |
| `DEC-xxx` | プロジェクトの決定ログで決裁済みの決定（LAB-1、LAB-2） |
| `PRM-xxx` | LAB-1の見積の前提条件（前提条件。顧客に送付した概算見積書の付録Aに掲載） |
| `E-xx` | 顧客への質問（確認事項一覧）。実際の回答はまだない |
| `SC-xx-yy` / `FT-xx-yy` | LAB-1の画面一覧および機能詳細一覧における画面ID / 機能ID |
| `M01`–`M24` | LAB-2プロトタイプで模擬または簡略化した部分（モック一覧 版1.2） |
| `L4-Axx` | LAB-4で新たに置いた前提（3節） |
| `L4-Dxx` | LAB-4で確定した決定（5節。「決定者」欄に受講者かPLかを記載） |
| **【模擬】** | 模擬顧客（顧客役を演じるエージェント）の回答に基づく前提 — 根拠のある前提であり、**実在の顧客が確認したものではない**。実在の顧客に当たるものはRFPのみ |
| 確度 | `RFP` = RFPに規定あり · `KH-GL` = 顧客（模擬）**【模擬】** · `PL` = Sun*が独自に設定、まだ誰も確認していない |

業務用語: 相対取引（主要フロー、取引額の約90%）、せり（副次フロー、約10%）、仲卸（仲介の卸売業者。**許可**が必要 — 審査を伴う許可）、売買参加者（売買に参加する者。**承認**が必要 — 手続きは比較的軽い）、完納奨励金（期日どおり全額支払った場合の奨励金）、日次締め（業務日の締め処理）、修正申請（確定後の修正の申請）、目利き（鮮度・品質を目で評価すること）。

## 1. LAB-4で確定した方向性（一本化）

### 1.1 LAB-1 にあった方向性

| LAB-1 で複数の方向があった点 | 方向 | LAB-1 の最終状態 |
|---|---|---|
| スコープのパターン | A（最小 ~70 MM）· B（P0+P1を完全に含む ~80 MM）· C（B + オプション） | **「Baseline（P0+P1を完全に含む）」の1案のみ**に絞られた。オプションは別行の価格になった（DEC-006 → DEC-008） |
| 契約価格と上限6,000万JPYの比較 | 上限62,5M + G1ゲート後の目標（バッファ10%）（DEC-019, DEC-021, DEC-022）· 削減パッケージ R1 / R2 / R3 | **R1**: 契約価格は固定 59,821,965 JPY 税抜、バッファ15%、G1 10%の仕組みは全面廃止（DEC-031, DEC-032） |
| 第1期での簡素化 | 17項目 「第2期以降にご提案」（例: 外部参加者向けページ、運用パラメータ画面） | 第1期の範囲外。第1期には代替の方法がある（概算見積書 §7.1） |
| オプション | 15行（遠隔取引 + 買受人ポータル、分析 / 予測、AI suggestion-only、タグ / ロットのスキャン、…） | 価格を分離し、上限の外（ルール6、PRM-024） |
| 本番基盤 | AWS Tokyo マネージド（主）· Vercel + Supabase（予備） | 提案書とTCOは **AWS Tokyo** による（DEC-002, DEC-018）。LAB-2プロトタイプは Vercel + Supabase で稼働 |

### 1.2 確定事項

**LAB-4は、LAB-1最終版の契約（パッケージR1）に従い、第1期の範囲どおりに設計する:**

| 項目 | 確定値 | 出典 |
|---|---|---|
| 機能の範囲 | P0 + P1、SCOPE-01..06 · **99機能（FT）/ 70画面 + 10バッチ** | DEC-008, DEC-031 |
| Effort / 価格（照合用。LAB-4では再見積しない） | バッファ前 74,313 MM · 59,821,965 JPY 税抜 / 65,804,162 税込 · バッファ15%固定 | DEC-031, DEC-032 |
| 確約済みの第1期の簡素化 | K1 運用パラメータ → 設定ファイル、SC-10-06 はなし（PRM-126）· K2 取引取消 は SC-04-05 上の専用ボタン（PRM-127）· K3 ロット属性の修正は SC-03-04 で（PRM-128）· K4 代行者 は SC-02-03 のタブ（PRM-129）· K7 通知は SC-00-03 上（PRM-130） | DEC-031 |
| オプション + 第2期の17項目 | **詳細設計はしない。** アーキテクチャには名前付きの拡張ポイントのみ残す（例: 外部向けページの境界、AI suggestion-only は必ず確定者を経由する境界） | ルール6; SCOPE-OUT-03/04/06; CAP-HUMAN-01 |
| to-beの基盤 | DEC-002 に従う **AWS Tokyo マネージド**。Vercel + Supabase は不採用案（ADRに記載）、LAB-2プロトタイプは試作にすぎない | DEC-002; L4-D01（5節） |

**この方向性を選んだ理由:**

1. LAB-1のシナリオで顧客と合意した範囲だから。この範囲と異なる設計をすると、LAB-5で契約と合わないタスクに分解されてしまう。
2. LAB-1のほかの方向性は、いずれも記録に残る決定で終了している（DEC-008, DEC-031）。再び開けばLAB-1をやり直すことになる。
3. オプションと第2期を外に置くことで、ルール6（オプションは範囲・前提・費用・リスクを常に分けて扱う）を守り、誰も対価を払わないものを設計することを避ける。
4. LAB-2プロトタイプは中核部分が実際に動くことの証拠であり、範囲の根拠ではない。プロトタイプとLAB-1が異なる箇所は、4節に記録された新しい決定がない限り **LAB-1が優先**する。
