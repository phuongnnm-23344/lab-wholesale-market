# 画面の共通枠と状態

このフォルダのすべての wireframe は、以下の共通枠と状態ブロックを使用します。各 wireframe は画面ごとの項目番号（1, 2, 3…）のみを独自に振ります。共通項目は接頭辞 `C-` を付け、各画面では番号を振り直しません。P3 では両方の番号を Screen Specification BM-2-901-51 の No 列に使います：`C-` の番号は `specs/_common/` に 1 回だけ記載し、画面の番号はここの順序を保ちます。

**番号を安定させるルール：** 項目を追加 → 末尾に次の番号を付ける（途中に挿入しない）；項目を削除 → 番号は保持し、項目表に「(削除)」と記載する。版をまたいで番号を振り直さない。

## 4. 共通の状態

| No | 状態 | タイミング | 表示 | 操作 | 出典 |
|---|---|---|---|---|---|
| C-20 | 読み込み中 | API 呼び出しが 300 ms 超 | 内容領域にスケルトン（骨組み）、主要ボタンは薄く表示 | — | NFR-PERF-01 |
| C-21 | 空 | データなし | 点線の枠 + 空の理由と次の操作を明記（例：「本日の販売公開ロットはありません。ロット一覧で公開してください →」） | 関連画面へのリンク | — |
| C-22 | 入力エラー | クライアント側の検証 / 422（`E-CMN-007` または機能コード — DEC-052, `specs/_common/api-conventions.md`） | 誤ったフィールドの**直下に赤い文字** + 赤枠；カーソルは最初の誤りへ。トーストだけに頼らない | 入力欄を修正 | FB LAB-2 #4 |
| C-23 | 業務エラー | 409（`CONFLICT:` SL の変更、重複確定、枠超過） | フォーム上のエラーボックス、原因と実際の数値を表示（例：「残数量が 12kg に変わりました」） | 数値を再読み込み、再試行 | ADR-004 |
| C-24 | **業務日ロック済み（423）** = SC-00-05 | API が 423 `DAY_LOCKED` / 期がロック済みを返した | 黄色のバナー：「2027/08/02 は締め済みのため直接修正できません。訂正は修正申請で行います。」+ ボタン「修正申請を作成 →」（SC-08-01、取引コードを引き継ぐ）。ロック済みフォームは閲覧のみ。**入力中に 423 が発生した場合**（入力途中で日がロック）：入力した内容は消さず、ボタンでその内容を SC-08-01 に引き継ぐ（例：SC-04-05 — 顧客 #5） | → SC-08-01 | BR-CLOSE-01, FT-08-04, ADR-005 |
| C-25 | 権限なし | 403 または役割に記録欄がない | 項目は閲覧のみ；記録ボタンは非表示（誤解を招く淡色表示はしない）；URL を直接開くと「この画面を表示する権限がありません」のページ | — | TBL-ROLE-01, L4-A06 |
| C-26 | システムエラー | 5xx / タイムアウト | 赤いバナー + IT に伝えるためのエラーコード；入力中のデータは保持 | 再試行 | NFR-OPS-01 |
| C-27 | **決裁待ち** | レコードに修正申請 / 版 / 資格変更の待ちがある | レコード横に「決裁待ち（1次）」/「決裁待ち（2次）」/「確認待ち」のラベル；編集ボタンは非表示；申請へのリンク。**内部の手順に「承認待ち」は使わない** — 承認 は 承認（売買参加者）にのみ使う（原則2、PRM-121, L4-D03；顧客 #19） | → SC-08-03 / SC-10-04 / SC-01-05 | FR-CORR-02, GOV-RULE-01 |
| C-28 | **通信断** | 接続が切れた | ヘッダー直下に赤い帯（固定）：「オフライン — 未同期 3件（最終同期 04:12）」。オフラインが許される画面（仮受付、引渡し、紙伝票後入力）はローカル保存を継続。確定画面（相対、せり確認）と**すべての決裁操作はブロック**され、「通信が回復するまで確定できません。紙伝票で継続してください」と表示 | 通信が戻ったら、競合がある場合は「同期・照合へ」ボタン（SC-03-07） | ADR-008, L4-A05, DEC-004 |
| C-29 | 通信復帰 | C-28 の後 | 緑のバナー 5 秒：「オンラインに復帰しました。未同期 3件を送信中…」；直前に押した操作は 確定済 / 未確定 を表示 | — | ADR-008 |
| C-30 | **MFA step-up** | PREMISE §3.2 の操作の前に、有効な MFA がない | ダイアログ：「この操作の前に本人確認を行います」+ 6 桁コードの入力欄 +「確認」/「キャンセル」；小さい文字：「確認後 10 分間、同じ利用者・同じ端末では再入力不要です（3 分操作がないと無効）」。**取り消せない操作**（日次締め、期ロック、規則のロールバック、物理削除の決裁）は**必ず再度コードを求める**。タブレットでは SC-06-02 と同様に**大きなテンキー**、小さな画面キーボードは出さない（顧客 #23）。5 回失敗 → 一時ロック。オフライン → 開かず、C-28 を表示 | コードを入力（アプリまたはハードウェアトークン — ADR-002） | ADR-002, PREMISE §3.2, L4-A07 |
| C-31 | 取り消せない操作の確認 | 日次締め、期ロック、せり確定、決裁 | ダイアログで**結果**を文で明示（例：「締めた後は解除できません」）+ 主要な数値；主ボタンは正確な操作名 | — | ADR-005 |

決裁操作を押したときの順序：条件をチェック（クライアント）→ C-31 確認 → C-30 MFA（必要な場合）→ API 呼び出し → C-12 トーストまたは C-23 / C-24。
